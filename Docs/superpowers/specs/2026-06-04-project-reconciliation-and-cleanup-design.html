1Why this pass exists

The repository currently describes two different projects at once.

The docs say (new)

  • One biom.Table feature table; no AbundanceMatrix wrapper.
  • Five operation kinds; computation delegated to the library palette.
  • Numbered phase workspaces: 0_inputs / 1_build / 2_transform / 3_analyze.
  • Agent-driven, exemplified by Workspaces/ABX_new.

The code still does (old)

  • askslm/__init__.py re-exports Engines.MetadataEngine / TaxonomyEngine.
  • Agents/tools import Engines.TaxonomyEngine.abundance_matrix.AbundanceMatrix — the retired wrapper.
  • Accessors/matrix_writers (maaslin / relative / counts) — the old write path.
  • Managers/, resolve, build_cohort, selector contracts — the old lean-core API.
A naïve "delete the old layers" would break the survivors. The dependency trace below distinguishes load-bearing code (used by ABX_new, the scaffold CLI, the agent, or the web app) from genuinely dead code. The reconciliation deletes the latter and rewires the former onto the feature-table model.

2The durable project definition LOCKED

Replaces the SRA-specific overview and the layer-architecture table. Written to last.

Ask-SLM is a workbench that makes metagenomic analysis easy and reproducible. The user works entirely through a web UI, chatting with an LLM agent that builds and analyzes the study with them — from raw inputs to results — and answers questions about the data along the way.

The agent works by authoring and running Python against the askslm package and established libraries (biom, ete3, scikit-bio, scipy, pandas), standardizing everything into one structure: a biom feature table (counts + sample metadata + feature lineage).

Each study is a reproducible workspace: a plain folder of files on disk (Python scripts, .biom tables, CSVs, plots), organized into phases (build → transform → analyze). The disk is the source of truth — the web UI is the driver, not a walled garden, so the user or any other application can open, view, or edit anything directly. Workspaces/ABX_new is the canonical example.

The domain today is metagenomics; the structure is general enough to extend.

Why this shape

It names the interaction model (web ↔ agent), the agent's mechanism (run Python over a toolbox), the one data structure, the filesystem-first contract, and a concrete example — none of which churns weekly. It deliberately omits the internal layer table, the command list, and SRA specifics, which did churn.

4The agent surface LOCKED

The interaction model decides this: the agent achieves goals by running Python, not by calling narrow pre-baked domain tools.

The agent authors and runs Python — exactly like the ABX_new phase scripts — using askslm, the libraries, and the scaffold CLI. So:

Agent toolFate
run_python (the wildcard executor)keep — the primary mechanism
session tools, registrykeep — session/state plumbing
taxonomy_tools.py, metadata_tools.py (narrow, AbundanceMatrix-coupled)delete — the old narrow-tool model

Consequence

The agent loses one-shot tools like "build an abundance matrix." Feature tables are instead built by the agent writing a build.py (via run_python + the scaffold CLI), which is how ABX_new already works. The agent's whole capability stays intact — the how changes from rigid tools to authored Python. Deleting these two files removes the last importers of AbundanceMatrix and the old contracts, unlocking §3.

Why src/ peers

It matches "consolidate under src/", ends the ask_slm-vs-askslm egg-info split, and mirrors the product's own shape: askslm is the reusable toolbox, agent + web are the application. pyproject's packages.find changes where = ["src"], include the three packages.

Import churn is real and must be done in one move. Engine/Accessor code moving into askslm/ means every surviving import path changes (Engines.MetadataEngine → askslm.metadata, etc.), in askslm, agent, web, and Tests/. The implementation plan treats the move + import rewrite as a single atomic step, gated by the test suite.

8Order of work

Sequenced so the tree is never broken between steps; each step ends green.

  1. Rewire, then delete. Trim askslm/__init__.py + contracts.py; delete the two narrow agent tool files and their registrations. Now nothing imports the dead code.
  2. Delete dead code + its tests (§3 "dies" table; remove matching Tests/ files).
  3. Move surviving domain code into src/askslm/, move Agents/→src/agent/, Web/→src/web/; rewrite every import; update pyproject + askslm.py. Atomic, test-gated.
  4. Junk sweep + .gitignore (§6): delete the old Docs (no archive), notebooks, build junk.
  5. Reframe the three docs (§7).
  6. Verify (§9): suite green + ABX_new phase chain runs end-to-end.

9Out of scope

  • The Web UI re-spec — this pass clears the ground; the new UI spec is the next, separate effort.

  • Re-architecting the agent — only the tool surface is reconciled (§4); the loop/session machinery is unchanged.
