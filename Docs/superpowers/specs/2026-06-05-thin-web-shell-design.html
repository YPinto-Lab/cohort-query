Thin web shell — chat + biom viewer

The only two things no off-the-shelf app does well: talk to the agent, and read a .biom file. Everything else — reading, editing, running, viewing plots — is handed to the apps the data scientist already uses. A small surface on the existing FastAPI skeleton; usable and demoable.

0Goal & philosophy LOCKED

A thin web shell that does only what has no good substitute, and delegates the rest.

Ask-SLM is an LLM agent that authors and runs .py phase scripts inside a workspace folder, where the disk is the source of truth. Of the user's jobs — chat, read code, edit code, run phases, view biom data, view results — four are already solved superbly by tools the data scientist owns (VS Code, PyCharm, Jupyter, the terminal, the OS file browser, an image viewer). Rebuilding those would be reinventing the wheel and would turn the UI into the "walled garden" CLAUDE.md warns against.

So the shell builds only the two irreducible surfaces: a chat to drive the agent, and a biom viewer (no other app opens .biom well). Code reading/editing, running, and results are reached by opening files/folders in the user's own apps.

Why a web UI at all (vs. terminal-only)

A pure-terminal MVP was seriously considered and is cheaper, but two things break it: viewing a wide numeric matrix in a terminal is genuinely bad, and a terminal demo undersells the product. The thin web shell keeps the build small while staying demoable. A full SPA/React rebuild was rejected as unnecessary for an MVP.

2Architecture LOCKED

Extend the existing src/web skeleton. No new frontend framework.

Stack: FastAPI + Jinja templates + htmx + SSE — all already present in app.py — plus a small amount of vanilla JS for tab switching, tree collapse, and table paging. Dependencies flow downward as today: web calls askslm and the agent, never the reverse.

# new + changed files under src/web/
src/web/
  app.py                      # + routes: biom view, biom table page, open-in-app, workspace create/switch
  biom_view.py        (new)   # load a .biom -> windowed Counts / Samples / Lineage frames
  workspace_diff.py   (new)   # snapshot workspace before/after a turn -> files-changed list
  biom_index.py       (new)   # enumerate a workspace's .biom outputs as a phase tree
  os_open.py          (new)   # open a path in the OS default app (open / xdg-open), with fallback
  templates/
    home.html         (new)   # workspace cards + New workspace
    chat.html      (rewrite)  # dark, two-column split shell
    _files.html       (new)   # files-changed list (open / view pills)
    _biom_tree.html   (new)   # collapsible phase tree + filter
    _biom_table.html  (new)   # one windowed table fragment + banner + pagers

Units & responsibilities

  • biom_view — the only genuinely new logic. Reuses biom.load_table + pandas; given a .biom path, a tab, and a window (row/col offset+limit) returns a sliced frame. No custom math.
  • workspace_diff — pure function: {path: mtime} snapshot before a turn, diff after → changed paths tagged py / biom / other. Decoupled from how the agent writes files.
  • biom_index — walks the workspace, groups .biom files under their phase (build / transform / analyze) with shape (features×samples) for labels.
  • os_open — validates a path is inside the workspace, then launches the OS default app; on failure returns the absolute path for manual opening.
  • templates — dumb rendering of the above into the dark two-column shell.

4Chat pane LOCKED

  • Streamed prose over the existing SSE stream (POST /w/{ws}/messages).
  • Collapsed code — the Python/commands the agent ran are captured but hidden behind a "show code & commands" toggle (transparency without clutter).
  • Files-changed list at the end of each turn, from workspace_diff:
    • .py / other → open ↗ pill → opens in the user's default editor.
    • .biom → view → pill → loads in the data pane (and selects it in the tree).
  • Open workspace folder button in the top bar → opens the workspace dir in the OS file browser.

5Data pane — biom viewer LOCKED

Navigation: collapsible phase tree

From biom_index: a tree grouping .biom outputs under ① build → ② transform → ③ analyze, leaves labeled by name + shape. A filter box narrows the tree by typing — this is how "many many" files stay navigable. The tree collapses to a thin rail.

6Large-data handling LOCKED

The matrix is never fully loaded into the DOM. The server sends a window; the UI states what's cut.

ConcernRule
Row window (features)page size 100; Prev/Next pager.
Column window (samples)page size 60; Prev/Next pager (Counts tab only).
Hard cap per fragment≈ 100 × 60 = 6,000 cells.
Disclosurealways-present banner: "Showing features 1–100 of N and samples 1–60 of M…" — no silent truncation.
Scroll UInative vertical + horizontal scroll inside the window; sticky header row (sample ids) and sticky first column (feature labels).
Escape hatchbanner reminds the user they can open the .biom in their own tools for the full matrix.

Samples and Lineage tabs are narrow (few columns) but can be long — they use the same row pager; no column window needed.

Defaults, tunable

100×60 are config constants in biom_view, easy to retune (e.g. 200 rows) without touching templates.

7Workspaces — open, switch, create LOCKED

  • Home page (GET /, rewritten home.html) — workspace cards (name + quick stats) and a ＋ New workspace card. Entry point.
  • In-app switcher — the workspace name in the top bar is a dropdown: jump to another workspace, or ＋ New workspace…, without going home.
  • Create — asks for a name → server runs the existing askslm workspace new <name> CLI → opens the new (empty) workspace. Inputs are added via Open workspace folder or by asking the agent. No upload widget in the MVP.

9Error handling LOCKED

  • Path safety — open and biom routes resolve the path and reject anything outside the workspace (reuse the existing _safe_workspace_dir guard pattern).
  • Bad / unreadable .biom — viewer fragment shows an inline error; page survives.
  • open-in-app failure (headless / no handler) — fall back to returning the copyable absolute path.
  • Agent errors — already surfaced by the existing event stream; unchanged.
  • Create with duplicate name — surface the CLI's error inline on the home page.
Consistent with project philosophy: trust input, fail fast. Validation lives only at the boundary (route guards); no defensive checks scattered through the viewer.

10Testing LOCKED

  • biom_view — unit tests against a small fixture .biom: correct rows/cols per tab, window slicing math, banner counts, lineage as its own view (no merge).
  • workspace_diff — create/modify/delete files in a temp dir; assert the tagged diff.
  • biom_index — fixture workspace with several .biom across phases → expected tree.
  • os_open / route guard — reject path traversal; OS call mocked.
  • web smoke — load shell, post a message (mock LLM), assert files-changed + biom fragments render. Fits existing Tests/web/.

11Explicitly out of scope (MVP) LOCKED

  • In-browser code editor or file browser — use the user's own apps.
  • Drag-and-drop input upload — add inputs via the folder or the agent.
  • In-browser plot/CSV rendering — opened in the OS viewer.
  • Auth / multi-user — single local user (existing cookie session is enough).
  • Charts / diversity plots in the viewer — it shows raw tables only.
