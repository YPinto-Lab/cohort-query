askslm — architecture: HLD & LLD

Companion to the design spec. Layers, contracts, types, and the per-class low-level design.

2026-06-17 · audience: backend engineer · style: Clean Code / SOLID (see .claude/skills/clean-code-style). Parent spec: 2026-06-17-askslm-sra-metalog-cohort-design.html. Diagrams: Mermaid.

A. High-Level Design

A.1 Architectural style

A small layered / hexagonal package. The domain core knows nothing about DuckDB, Gemini, or the filesystem; those are adapters behind Protocol ports. A single composition root (Runtime) wires concretes to ports. The Jupyter-facing module functions (config, ask, load_plan) are a thin facade over the composition root — they hold no logic.

Domain depends on nothing. Services depend on domain + ports. Adapters implement ports. This is the seam that lets every service be unit-tested against fakes and lets the LLM provider or the database engine be swapped without touching the core.

A.2 Layers & responsibilities

LayerMembersKnows about
Facadeconfig(), ask(), load_plan(), re-exported Profilercomposition root only
Composition rootSettings, Runtimeevery concrete; wires ports
Application servicesAskService, CohortEstimator, CohortBuilderdomain + ports
Domain corePlan, Translation, ResearchQuestion, Cohort, ProfileMatrix, ReconciledMetadata, DropReport, CohortEstimate, Profilernothing
Ports (Protocols)LlmBackend, Databasedomain types only
AdaptersGeminiBackend, DuckDbConnection, PlanRepository, BiomFactory, and the readersthird-party libs

A.3 The two ports

Everything that touches the network (the LLM) or the disk (the DuckDB file) lives behind one of two single-method ports. The readers are composed from Database — they are domain logic expressed as SQL, not new I/O boundaries.

A.4 Control flow — three sequences

ask() — translate, estimate, persist

plan.run(out) — discover, pull, reconcile, assemble

load_plan(path).run(out) — reproduce without the LLM

One public class per file (clean-code rule 4). Packages mirror the layers.

A.6 Reuse from the existing codebase

  • sra_schema.py (SRAMetadataSchema, SRATaxonomySchema) feeds SchemaCatalog — the column inventory the LLM is grounded on. No re-description.
  • The current biom build path (counts + lineage feature metadata + sample metadata) is wrapped by BiomFactory; the assembly rules do not change.
  • Reconciliation keeps two DataFrames (per the standing rule): metadata and lineage never merge into one frame. ReconciledMetadata is sample metadata only; lineage rides on the biom's feature axis.

B. Low-Level Design

B.1 Domain value objects (frozen dataclasses)

All inputs/outputs crossing a seam are typed domain objects, never bare str/dict/ DataFrame. Accession is a NewType(str) for type clarity; the real object is Cohort, which owns the set semantics.

Accession = NewType("Accession", str)

class Source(Enum):
    SRA = "sra"
    METALOG = "metalog"

@dataclass(frozen=True)
class ResearchQuestion:
    text: str
    profiler: Profiler

@dataclass(frozen=True)
class SourceQuery:
    source: Source
    sql: str

@dataclass(frozen=True)
class QueryInterpretation:
    restatement: str                 # one English line per understood filter
    filters: tuple[str, ...]

@dataclass(frozen=True)
class Translation:                    # the LlmBackend output, before any DB hit
    interpretation: QueryInterpretation
    sra_query: SourceQuery
    metalog_query: SourceQuery

@dataclass(frozen=True)
class CohortEstimate:
    sra: int
    metalog: int
    union: int
    with_profile: int
    dropped: int

B.2 Profiler — the closed set, single source of truth

The enum member carries its ProfilerSpec: which source, which DuckDB table, and the column that holds lineage. Nothing else in the system hard-codes a table name for a profiler.

@dataclass(frozen=True)
class ProfilerSpec:
    source: Source
    table: str
    lineage_column: str

class Profiler(Enum):
    SRA_TAXONOMY       = ProfilerSpec(Source.SRA,     "sra_taxonomy",      "lineage")
    MOTUS3             = ProfilerSpec(Source.METALOG, "motus3",            "clade")
    SPIRE_MOTUS        = ProfilerSpec(Source.METALOG, "spire_motus",       "clade")
    METAPHLAN4_ALL     = ProfilerSpec(Source.METALOG, "metaphlan4_all",    "clade")
    METAPHLAN4_SPECIES = ProfilerSpec(Source.METALOG, "metaphlan4_species","clade")

    def spec(self) -> ProfilerSpec:
        return self.value

B.3 Composition root — Settings & Runtime

Settings validates on construction (fail fast, rule from the spec). Runtime is the single place concretes are named; it builds wired services on demand. The facade reads one module-level Runtime set by config().

@dataclass(frozen=True)
class Settings:
    db_path: Path
    llm: str
    llm_key: str

    def __post_init__(self):
        self._require(self.db_path.exists(), "database file not found")   # fail fast at config()
        self._require(bool(self.llm_key), "missing LLM key")

class Runtime:
    def __init__(self, settings: Settings):
        self._settings = settings

    def ask_service(self) -> AskService:
        return AskService(self._translator(), self._estimator(), self._repository())

    def cohort_builder(self) -> CohortBuilder:
        return CohortBuilder(self._discovery(), self._profiles(), self._metadata(), self._factory())

Private builders (_translator, _database, …) each return one wired concrete and stay one line. _database() opens the DuckDB file read-only and is shared by the readers.

B.4 Translation — Translator + GeminiBackend

Translator orchestrates; GeminiBackend is the only class that imports the Gemini SDK. The prompt is a typed DTO so the port stays at one parameter.

@dataclass(frozen=True)
class TranslationPrompt:
    question: ResearchQuestion
    sra_schema: str
    metalog_schema: str

class Translator:
    def __init__(self, backend: LlmBackend, catalog: SchemaCatalog):
        self._backend = backend
        self._catalog = catalog

    def translate(self, question: ResearchQuestion) -> Translation:
        prompt = self._prompt_for(question)
        return self._backend.translate(prompt)

    def _prompt_for(self, question: ResearchQuestion) -> TranslationPrompt:
        return TranslationPrompt(question=question,
                                sra_schema=self._catalog.sra(),
                                metalog_schema=self._catalog.metalog())

An invalid-SQL result is not caught here — it surfaces when CohortEstimator runs EXPLAIN against the DB (B.6). That keeps the network step pure and pushes the "is this SQL real?" question to the component that owns the DB.

B.5 Plan, PlanView, PlanRepository

Plan is a serializable document plus two thin behaviors: render (_repr_html_, delegated to PlanView) and run (sugar delegating to the active Runtime's CohortBuilder). The on-disk form is the Plan: JSON via asdict, Profiler stored by name.

@dataclass(frozen=True)
class Plan:
    question: ResearchQuestion
    translation: Translation
    estimate: CohortEstimate
    error: str | None = None

    def run(self, out: Path) -> biom.Table:
        self._guard_runnable()                       # guard clause, no else
        return active_runtime().cohort_builder().build(self, out)

    def _guard_runnable(self):
        if self.error is not None:
            raise TranslationError(self.error)

    def _repr_html_(self) -> str:
        return PlanView(self).render()

Tradeoff, stated honestly: run() reaches the module-level runtime (a service locator). That couples the DTO to global config. The alternative — a separate RunnablePlan bound to services on load — was rejected as ceremony: the plan file must be runnable from a bare load_plan(path), so the runtime has to be ambient anyway. CohortBuilder.build(plan, out) remains the pure, injectable entry point; run() is only sugar over it.

class PlanRepository:
    def __init__(self, root: Path):
        self._root = root

    def save(self, plan: Plan, path: Path) -> Path:
        target = self._resolve(path, plan.question)   # explicit save= or plans/<slug>.json
        target.write_text(self._encode(plan))
        return target

    def load(self, path: Path) -> Plan:
        return self._decode(path.read_text())

B.6 AskService & CohortEstimator

class AskService:
    def __init__(self, translator: Translator, estimator: CohortEstimator, repository: PlanRepository):
        self._translator = translator
        self._estimator = estimator
        self._repository = repository

    def ask(self, question: ResearchQuestion, save: Path | None) -> Plan:
        translation = self._translator.translate(question)
        plan = self._planned(question, translation)
        self._repository.save(plan, save)
        return plan

    def _planned(self, question: ResearchQuestion, translation: Translation) -> Plan:
        estimate = self._estimator.estimate(translation, question.profiler)
        return Plan(question=question, translation=translation, estimate=estimate)

CohortEstimator runs only cheap aggregates: a COUNT per source query and a coverage count for the chosen profiler. It is also where invalid SQL is detected (the count fails) and turned into a Plan carrying error instead of an estimate — so review still renders, and run() refuses.

B.7 The cohort engine — CohortBuilder and its collaborators

class CohortBuilder:
    def __init__(self, discovery: CohortDiscovery, profiles: ProfileReader,
                 metadata: MetadataReader, factory: BiomFactory):
        self._discovery = discovery
        self._profiles = profiles
        self._metadata = metadata
        self._factory = factory

    def build(self, plan: Plan, out: Path) -> biom.Table:
        cohort = self._discovery.discover(plan.translation.sra_query, plan.translation.metalog_query)
        matrix = self._profiles.read(plan.question.profiler, cohort.union())
        metadata = self._metadata.reconciled(cohort)
        table = self._factory.build(matrix, metadata.restricted_to(matrix.accessions()))
        return self._written(table, out, DropReport.between(cohort.union(), matrix.accessions()))

Each collaborator is single-purpose and independently testable:

ClassSignatureDomain effect
CohortDiscoverydiscover(sra_query, metalog_query) -> Cohortrun both SELECTs via Database; union accessions into a Cohort (keeps the two source sets distinct internally).
ProfileReaderread(profiler, accessions) -> ProfileMatrixpull the chosen profiler's table for those accessions; the matrix's columns define which samples actually have the profile.
MetadataReaderreconciled(cohort) -> ReconciledMetadataread SRA + Metalog metadata for the cohort and hand both frames to MetadataReconciler.
MetadataReconcilerreconcile(sra, metalog) -> ReconciledMetadataMetalog wins per accession; SRA fills gaps and SRA-only samples.
BiomFactorybuild(matrix, metadata) -> biom.Tableassemble the single-feature-space table; lineage rides the feature axis.
DropReportbetween(requested, present) -> DropReportset difference: cohort accessions with no profile, reported never silently kept.

B.8 The Metalog-wins merge (the one subtle line)

Reconciliation is a single domain operation with an opaque library call, so it gets an extracted method and a why-comment on the cryptic call (clean-code rule 5):

class MetadataReconciler:
    def reconcile(self, sra: pandas.DataFrame, metalog: pandas.DataFrame) -> ReconciledMetadata:
        merged = metalog.combine_first(sra)          # Metalog row wins; SRA fills gaps + SRA-only samples
        return ReconciledMetadata(merged)

Both frames are indexed by Accession. combine_first is precisely "left wins, right fills" — no hand-rolled column-by-column logic, no else.

B.9 ProfileMatrix / ReconciledMetadata — owning their invariants

@dataclass(frozen=True)
class ProfileMatrix:
    counts: pandas.DataFrame          # features × accessions, one feature space
    lineage: pandas.DataFrame         # feature → lineage; the biom feature axis

    def accessions(self) -> frozenset[Accession]:
        return frozenset(self.counts.columns)

@dataclass(frozen=True)
class ReconciledMetadata:
    frame: pandas.DataFrame           # indexed by Accession

    def restricted_to(self, accessions: frozenset[Accession]) -> ReconciledMetadata:
        return ReconciledMetadata(self.frame.loc[sorted(accessions)])

Callers never see .columns or .loc; the matrix answers "which samples do I cover?" and the metadata answers "restrict yourself to these." The DataFrame is an implementation detail behind the type.

B.10 Error model

ConditionWhereBehavior
Missing DB file / LLM keySettings.__post_init__ConfigError at config() — fail fast, nothing else constructed.
Invalid generated SQLCohortEstimator (EXPLAIN/COUNT)Plan returned with error set; review renders the error; run() raises TranslationError.
Profiler absent for whole cohortCohortBuilderwarning + empty biom.Table written — explicit, never silent success.
Genuinely bad data in DBadapterslet DuckDB / biom raise. No defensive validation past the config boundary (trust input, fail fast).

B.11 Testing strategy

  • Ports get fakes. FakeLlmBackend returns a canned Translation; FakeDatabase returns canned frames. Every service is unit-tested with zero network and zero disk. AAA, blank-line-separated.
  • Domain objects are pure — DropReport.between, combine_first merge, restricted_to tested directly on small fixtures.
  • One e2e wires real DuckDbConnection against a tiny fixture DuckDB (a handful of accessions across both sources, two profilers) and asserts the biom's feature space, dropped set, and Metalog-wins metadata. Mirrors the existing Tests/e2e shape.
  • Plan round-trip: save → load → equal Plan; load_plan(path).run() never touches LlmBackend.
