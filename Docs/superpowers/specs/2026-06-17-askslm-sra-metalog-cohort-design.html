askslm — from research question to analysis-ready cohort

Connecting SRA and Metalog into one biom for valid metagenomic meta-analysis.

Design spec · 2026-06-17 · Locked = settled in brainstorming · Proposed = open / assumption to confirm

1. Purpose & primary user Locked

Noam, a bioinformatician working in Jupyter notebooks. He has a research question ("fecal metagenomes from adults with IBD in Western countries") and wants the set of public metagenome samples that answer it — with metadata and taxonomic profiles that are comparable across studies, so a meta-analysis is actually valid.

The product is neither a query tool nor an analysis tool. It is the bridge that takes a researcher from research question → analysis-ready cohort of metagenome samples, by connecting SRA and Metalog. SRA alone is insufficient: its metadata is messy free-text and its counts are not comparable across studies. Metalog adds curated metadata and uniformly-produced taxonomic profiles. The connective tissue between the two is the sample/run accession.

2. Scope & boundary Locked

askslm is a read-only Python package (pip install askslm). It reads one shared, prebuilt DuckDB that already contains both SRA and Metalog (metadata + every profiler table), and emits one .biom.

  • In scope: natural-language → structured query, show-your-work + confirm, the SRA∪Metalog merge and reconciliation, building the biom, the Jupyter-facing API.
  • Out of scope: building or refreshing the mirror. The lab does that separately (the SRA→DuckDB side already exists; the Metalog ETL is a distinct, future effort). The package never writes to the shared DB.

4. The profilers Locked

Each is a taxonomic profiler Metalog (or the SRA pipeline) ran on the same samples. Each produces a distinct, non-interchangeable feature space — which is why one biom holds exactly one.

Enum memberFeature spaceNotes
SRA_TAXONOMYNCBI tax_id (nested-set)From the SRA-side pipeline; self_count/total_count.
MOTUS3mOTUs 3.0 OTUsMarker-gene; includes uncultivated species. Relative abundance.
SPIRE_MOTUSmOTUs OTUs (SPIRE)Same feature space as mOTUs3, different provenance/coverage.
METAPHLAN4_ALLNamed taxa, all ranksClade markers; full lineage phylum→strain.
METAPHLAN4_SPECIESNamed speciesSpecies-only; common meta-analysis choice.

mOTUs and MetaPhlAn IDs do not map to each other without a translation step; the SRA tax_id space is a third world. Hence one profiler per biom.

5. End-to-end flow Locked

1. pip install askslm

2. Configure once (path + provider/key resolved here, fail fast if missing):
   askslm.config(db="/mnt/lab/metalog_sra.duckdb", llm="gemini", llm_key=os.environ["..."])

3. Build a plan (the LLM reads every source's schema, writes ONE SQL per source).
   The plan is WRITTEN TO DISK on creation — the full object, self-contained.
   NOTE: no profiler here — ask() is the research question only.
   plan = askslm.ask(
       "fecal metagenomes from adults with IBD, Western countries",
       save="plans/ibd_western.json",
   )

4. Review — `plan` renders "show your work":
     • English restatement of the filters understood
     • the per-source SQL (SRA, Metalog, …)
     • cohort: 412 samples (SRA 380 ∪ Metalog 207)
     • per-profiler coverage so you can pick: metaphlan4_species 207, motus3 207, sra_taxonomy 380
     • policy: metadata → Metalog wins
   (Stats only? Stop here — you never needed a profiler.)

5. Execute — the feature space (profiler) is chosen HERE, at materialization:
   table = plan.run(profiler=askslm.Profiler.METAPHLAN4_SPECIES, out="cohort.biom")

   # reproduce later — same cohort, even a different profiler, no LLM call:
   askslm.load_plan("plans/ibd_western.json").run(profiler=askslm.Profiler.MOTUS3, out="cohort_motus.biom")
The plan file is the reproducible artifact. ask() persists the question, interpretation, per-source SQL, cohort preview, and db reference — but not a profiler, since that is a run() argument. Commit the plan next to the notebook; load_plan(...).run(profiler, out) reproduces the cohort in any feature space without re-invoking the LLM.

6. What plan.run() does — the merge Locked

  1. Discovery. Run both SQL strings on the DuckDB → accession set A (SRA) and B (Metalog). Cohort = A ∪ B.
  2. Counts. Pull the chosen profiler's matrix for the cohort accessions. Samples lacking that profiler are dropped and reported — never silently included. This defines the biom's single feature space.
  3. Sample metadata. Per accession, the Metalog row wins; SRA fills gaps and supplies SRA-only samples.
  4. Feature metadata. Lineage taken from the chosen profiler.
  5. Assemble. Build a biom.Table: counts × samples, reconciled sample metadata, profiler lineage as feature metadata. Reuses the existing biom build path.

8. Error handling Locked

  • Missing config (no DB path / no key): fail fast at config() / first ask() with a clear message.
  • Invalid LLM SQL: surfaced on the Plan as an error; Noam can refine the question (or hand-edit SQL on the plan) and re-run. Nothing executes until run().
  • Chosen profiler missing for the whole cohort: explicit warning; resulting biom is empty — no silent success.
  • Trust input, fail fast: no defensive validation beyond the config boundary; let the libraries (DuckDB, biom) raise on genuinely bad data.

9. Confirmed knobs Locked

  • save= on ask(): explicit path, defaulting to plans/<slug>.json when omitted.
  • Plan file format: JSON (human-diffable, commit-friendly).
  • Sample lacking the chosen profiler: dropped and reported (not kept as an all-zero column).
