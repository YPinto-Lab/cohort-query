askslm — from research question to analysis-ready cohort

Connecting SRA and Metalog into one biom for valid metagenomic meta-analysis.

Design spec · 2026-06-17 · Locked = settled in brainstorming · Proposed = open / assumption to confirm

1. Purpose & primary user Locked

Noam, a bioinformatician working in Jupyter notebooks. He has a research question ("fecal metagenomes from adults with IBD in Western countries") and wants the set of public metagenome samples that answer it — with metadata and taxonomic profiles that are comparable across studies, so a meta-analysis is actually valid.

The product is neither a query tool nor an analysis tool. It is the bridge that takes a researcher from research question → analysis-ready cohort of metagenome samples, by connecting SRA and Metalog. SRA alone is insufficient: its metadata is messy free-text and its counts are not comparable across studies. Metalog adds curated metadata and uniformly-produced taxonomic profiles. The connective tissue between the two is the sample/run accession.

2. Scope & boundary Locked

askslm is a read-only Python package (pip install askslm). It reads one shared, prebuilt DuckDB that already contains both SRA and Metalog (metadata + every profile table), and emits one .biom.

  • In scope: natural-language → structured query, show-your-work + confirm, the SRA∪Metalog merge and reconciliation, building the biom, the Jupyter-facing API.
  • Out of scope: building or refreshing the mirror. The lab does that separately (the SRA→DuckDB side already exists; the Metalog ETL is a distinct, future effort). The package never writes to the shared DB.

4. The sources Locked

Every DuckDB table is one Source with a kind. METADATA sources describe samples (reconcilable, per field). PROFILE sources feed counts; each belongs to a feature universe (its ID namespace) — sources sharing a universe combine into one biom.

SourceKindUniverseUnitRole / notes
SRA_METADATAMETADATA——Messy free-text; SRA run/sample fields.
METALOG_METADATAMETADATA——Default winner — curated, comparable.
SRA_TAXONOMYPROFILENCBI_TAXONOMYcountsSTAT pipeline; self_count/total_count (→ normalized).
METALOG_METAPHLAN4_ALLPROFILENCBI_TAXONOMYrelativeClade markers; full lineage phylum→strain; tax_ids.
METALOG_METAPHLAN4_SPECIESPROFILENCBI_TAXONOMYrelativeSpecies-only; common meta-analysis choice.
METALOG_MOTUS3PROFILEMOTUSrelativeMarker-gene; uncultivated species.
METALOG_SPIRE_MOTUSPROFILEMOTUSrelativeSame mOTU IDs, different coverage.

Within a universe (e.g. STAT + MetaPhlAn both speak NCBI tax_id) sources combine by winner + per-sample fill, after normalizing counts to relative abundance. Across universes (mOTUs ≠ NCBI tax_id) they never share a biom.

5. End-to-end flow Locked

1. pip install askslm

2. Configure once (path + provider/key resolved here, fail fast if missing):
   askslm.config(db="/mnt/lab/metalog_sra.duckdb", llm="gemini", llm_key=os.environ["..."])

3. Build a plan (the LLM reads every source's schema, writes ONE SQL per source).
   The plan is WRITTEN TO DISK on creation — the full object, self-contained.
   NOTE: no source choices here — ask() is the research question only.
   plan = askslm.ask(
       "fecal metagenomes from adults with IBD, Western countries",
       save="plans/ibd_western.json",
   )

4. Review — `plan` renders "show your work":
     • English restatement of the filters understood
     • the per-source SQL (SRA, Metalog, …)
     • cohort partition: SRA-only 205, Metalog-only 32, shared 175  (overlaps made visible)
     • per profile-source coverage so you can pick:
         metalog_metaphlan4_species 207, metalog_motus3 207, sra_taxonomy 380
   (Stats only? Stop here — no materialization needed.)

5. Execute — winning sources chosen HERE; both are Sources:
   # profile winner heads the NCBI_TAXONOMY universe; STAT fills samples MetaPhlAn lacks;
   # all counts normalized to relative abundance.
   table = plan.run(profile_winning_source=askslm.Source.METALOG_METAPHLAN4_SPECIES,
                    metadata_winning_source=askslm.Source.METALOG_METADATA,  # resolves the 175 shared
                    out="cohort.biom")

   # reproduce later — same cohort, a different universe, no LLM call:
   askslm.load_plan("plans/ibd_western.json").run(profile_winning_source=askslm.Source.METALOG_MOTUS3, out="cohort_motus.biom")
The plan file is the reproducible artifact. ask() persists the question, interpretation, per-source SQL, cohort preview, and db reference — but not the source choices, since those are run() arguments. Commit the plan next to the notebook; load_plan(...).run(profile_winning_source, metadata_winning_source, out) reproduces the cohort in any universe without re-invoking the LLM.

6. What plan.run() does — the merge Locked

  1. Discovery. Run both SQL strings → accessions per source; normalize to the canonical (biosample) level; cohort = the union, partitioned into SRA-only / Metalog-only / shared.
  2. Counts. Take the profile_winning_source's universe; read every source in it, normalize each to relative abundance, and fold per sample (winner's column wins, others fill the samples it lacks). Samples in no source of that universe are dropped and reported. This defines the biom's single feature space (the universe).
  3. Sample metadata. On shared samples the chosen metadata_winning_source wins (default METALOG_METADATA); remaining sources fill gaps per field by a fixed precedence order.
  4. Feature metadata. Lineage taken from the universe's sources (the winner's lineage column).
  5. Assemble. Build a biom.Table: counts × samples, reconciled sample metadata, profile lineage as feature metadata. Reuses the existing biom build path.

8. Error handling Locked

  • Missing config (no DB path / no key): fail fast at config() / first ask() with a clear message.
  • Invalid LLM SQL: surfaced on the Plan as an error; Noam can refine the question (or hand-edit SQL on the plan) and re-run. Nothing executes until run().
  • Winner's universe missing for the whole cohort (no source in it covers any sample): explicit warning; resulting biom is empty — no silent success.
  • Trust input, fail fast: no defensive validation beyond the config boundary; let the libraries (DuckDB, biom) raise on genuinely bad data.

9. Confirmed knobs Locked

  • save= on ask(): explicit path, defaulting to plans/<slug>.json when omitted.
  • Plan file format: JSON (human-diffable, commit-friendly).
  • Sample in none of the winner's universe sources: dropped and reported (not kept as an all-zero column).
  • Profile sources within a universe combine by winner + per-sample fill; counts normalized to relative abundance.
